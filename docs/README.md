# 原型界面文案审查 Skill

> **版本：v1.10.0**
> **用途：** 审查原型、截图、页面流程、文案清单与需求文档中的简体中文 UI 文案，并输出可直接交付团队处理的修改建议。

## 能力概览

| 能力 | 说明 |
|---|---|
| 可见文案审查 | 检查标题、导航、字段、占位符、按钮、弹窗、空状态和反馈提示。 |
| 一致性与状态闭环 | 对照同一对象、动作与状态在不同页面、组件和关键流程中的表达。 |
| 分层规则对齐 | 支持项目规范、PaletX/ZTE 设计系统（`PX-`）、系统提示句型（`SPT-`）和通用高频规则（`HF-`）。 |
| 可追溯结论 | 每个可验证问题保留原文、位置、直接改写、规则依据和影响范围。 |
| 自动交付 | 对可执行的 P0/P1/P2 问题自动生成可勾选的 Markdown 修改清单。 |
| 规范治理 | 将反复出现、冲突或缺失的规则单列为“规范待维护项”，而非只修单页文案。 |
| 规范覆盖缺口 | 单列未被现有规范覆盖的真实文案场景，供设计师决定是否新增场景、术语、格式或例外规则。 |
| 可选审查项 | 可按任务或页面启用、跳过或仅提示 `PX-`、`SPT-`、`HF-`、跨页面检查、规范缺口与修改清单。 |
| 维度确认引导 | 用户未指定范围时，先以易懂菜单确认检查维度或接受推荐组合，再执行审查。 |

## 适用与不适用范围

Skill 适用于 Web、移动端、后台系统、小程序和桌面端的**用户可见文本**。可使用截图、原型链接、录屏、文案表格、需求文档或混合材料。

它不替代产品、技术、安全、法务或品牌负责人对业务口径的最终确认。视觉布局、交互路径、功能正确性、模糊截图文字和未提供的业务定义不会被推断为文案缺陷；这些内容会标注为“未核实”“待确认”或“规范待维护项”。

## 规则优先级

```text
安全 / 法律 / 项目专属规范
        ↓
已确认的设计系统与提示信息规则（PX- / SPT-）
        ↓
通用高频规则（HF-）
        ↓
材料内语义明确且一致的既有口径
        ↓
建议统一
```

发生冲突时，以更高优先级为准。来源只在“已提炼”的范围内生效；无法验证的规则、失败原因、修复方式或英文口径不自动补写。

## 审查项可选配置

默认使用 `auto`：只有页面明确涉及 PaletX/ZTE 设计系统时才加载 `PX-`，只有出现成功、失败、错误或异常提示时才加载 `SPT-`。用户可按任务或页面覆盖该默认值。

| 指令示例 | 本次行为 |
|---|---|
| `本页不涉及 PX 规范，跳过 PX。` | 不加载 `PX-`，也不生成 PX 相关问题。 |
| `只查高频规则和错误提示。` | 启用 `HF-` 与 `SPT-`；跳过其他选择性模块。 |
| `页面 A 按 PX 审查，页面 B 不查 PX。` | 页面 A 启用 `PX-`，页面 B 跳过 `PX-`。 |
| `不生成规范缺口清单。` | 不输出 `UC-` 场景清单。 |
| `只提示未审查项，不生成修改清单。` | 保留范围说明，不输出独立 Markdown 修改清单。 |

每份报告都会在开头声明实际启用、跳过和仅提示的模块。项目安全、法律或其他明确强制规范不会因选择性配置被绕过；如用户要求排除，报告会将其记录为范围限制。

### 未指定检查范围时

当你仅说“审查这张图”或“检查这个页面”，Skill 会先追问一次，并提供下列易懂选项：**A 基础文案与页面一致性、B 状态与提示信息、C 设计系统与品牌规范、D 跨页面/流程一致性、E 规范缺口与治理建议、F Markdown 修改清单**。你只需回复如 `A、B、F`、`跳过 C`、`按推荐执行` 或 `完整审查`，无需了解内部规则编号。

若材料包含错误、成功、进度或风险提示，推荐组合为 **A + B + F**；多页面流程推荐 **A + D + F**；希望补全设计规范时推荐 **A + E + F**。已经明确“完整审查”“只查错误提示”或“本页跳过 PX”等范围时，不会重复追问。

## 输出方式

### 审查报告

报告按 P0–P3 分级，并先说明覆盖范围、规则基线和材料限制。每条可执行问题至少包含：**位置、原文、修改为、依据、影响范围**。P0/P1 用于关键理解、风险或流程冲突；P2 用于可验证的局部不一致；P3 仅用于没有明确规则冲突的优化建议。

### Markdown 修改清单

当存在原文、位置和直接改法均明确的 P0/P1/P2 问题时，Skill 自动生成 `*-copy-change-list.md`。清单默认使用复选框和 `COPY-` 编号，按优先级排序；术语、技术、安全、法务或业务口径不明确时，只进入待确认项。

当发现现有规范无法给出唯一结论的真实场景时，清单末尾会增加“未涉及规范场景文案”表格。该表格不代表文案错误，不使用 P0–P3，也不提供伪造的直接替换；它只记录场景证据、未覆盖原因、建议设计师评估和最小规范动作。

可直接提出以下指令调整交付方式：

| 指令 | 输出行为 |
|---|---|
| `生成修改清单` / `导出 Markdown` | 生成默认清单。 |
| `给开发直接替换` / `只改写文案` | 仅保留优先级、位置、原文、修改后文案和依据。 |
| `只要 P0/P1` | 仅输出高优先级问题。 |
| `按页面分组` | 按页面或流程组织条目。 |
| `包含 P3` | 增加可选优化分组。 |

## 常用调用方式

```text
按当前 Skill 审查这组原型截图，并生成给开发直接替换的 Markdown 清单。

按 PaletX 设计系统审查“成员邀请”流程，重点检查术语、按钮和状态反馈。

按系统产品提示信息规范审查以下错误提示，检查原因和修复方式是否完整。

只审查中英文混排、标点和数字单位，不检查业务术语。

本页不涉及 PX 规范，跳过 PX；仅检查上传失败提示和高频文案问题。

审查这批截图。→ Skill 会先给出 A–F 选项和推荐组合。

完整审查这批截图，并生成修改清单。→ 不追问，直接执行。
```

## 维护约定

规则、模板、来源、输出行为或 Skill 主流程发生修改后，必须同步更新 `VERSION_HISTORY.md`；若影响用户可见能力、使用方式、规则范围或已知限制，也必须更新本 README。文档同步完成后，先运行 `python3 scripts/validate_skill_consistency.py --strict`（含内部链接与机器专属路径扫描），再运行 Skill 结构校验；涉及 `SKILL.md`、审查流程或 description 的改动，再用 skill-creator 按 `evals/` 做回归与触发测试。
