# PaletX 文案规范：结构化审查基线

> **来源状态：已接入。** 本文件将 PaletX“文案”网页中已核实的高频规则转写为可审查条目；它不是原网页的完整镜像。读取原文、查询新增章节或发现本文件与原网页冲突时，以来源网页为准，并登记为待更新项。

## 元数据与优先级

| 字段 | 值 |
|---|---|
| 规范 ID | `PX-COPY` |
| 来源 | PaletX · 指引 · 文案 |
| 原始地址 | <https://paletx.zte.com.cn/#/guide/office-document> |
| 提取日期 | 2026-08-19（GMT+8） |
| 页面版本 | 页面未显示可识别版本号 |
| 适用语言 | 简体中文与面向全球用户的美式英语界面 |
| 使用状态 | 生效；仅覆盖已提炼规则 |
| 优先级 | 高于通用规则库，低于后续经确认的产品专属、法务或安全规范 |

当用户要求“按 PaletX / ZTE 设计系统审查”、提供的材料属于该设计系统，或当前项目明确采用此规范时，读取本文件与 `source-register.md`。报告中以 `PX-` 规则编号作为“依据”。如果截图或页面证据不足以判断组件语境，不要强行应用组件规则。

## 1. 基本原则与国际化

| 规则 ID | 可判定要求 | 审查示例 | 例外/说明 |
|---|---|---|---|
| PX-BASE-01 | 文案必须准确、清晰、一致、友好；避免让用户推断隐含含义。 | `配置异常` → 已知时改为 `保存配置失败，请检查服务地址。` | 原因未知时不要编造，应说明已知影响与下一步。 |
| PX-BASE-02 | 产品、术语、业务、系统、模块及同义菜单、选项、按钮必须采用一致写法；同类信息的大小写与句式也应一致。 | `eNodeB` 不应与 `E-NodeB`、`eNB`、`eNodeb` 混用。 | 概念层级不同且经术语表定义时可保留不同名称。 |
| PX-I18N-01 | 面向全球用户的英语界面采用美式英语，文案应考虑文化得体性。 | 项目内不要混用美式与英式拼写。 | 特定国家/地区定制版本可遵循当地语言规范。 |
| PX-I18N-02 | 英文文案使用正确拼写、语法与词性，避免难以理解的直译、长名词串、行话和未定义技术俚语。 | `Timing Export Task` → `Scheduled Export Task`。 | 面向开发者的代码、协议名称与字段值按官方写法保留。 |
| PX-I18N-03 | 使用中性、非歧视性且便于跨文化理解的表达；避免与特定文化、地域、货币或季节绑定的默认示例。 | 时间提示优先使用月份、季度或具体日期，而非季节。 | 合规、地区版或业务场景明确需要时，记录适用地区与例外。 |

## 2. 英文拼写、大小写、冠词与单复数

| 规则 ID | 可判定要求 | 审查示例 | 例外/说明 |
|---|---|---|---|
| PX-ENG-01 | 所有英文界面词必须正确拼写；不得任意造词、拆词或组合词。界面显示名应优先使用规范全称，避免非标准缩略语。 | `User Seg. Manager` → `User Segment Manager`。 | 脚本字段、API 字段、代码、外部系统原值不强制改写。 |
| PX-ENG-02 | 标题大小写适用于标题、按钮、菜单、参数名、左侧标签及图标 Tooltip：实词首字母大写；一般虚词小写；首尾词大写；构成动词短语的虚词大写。 | `Setting Port Numbers to Fixed Values`。 | 专有名词、缩略语按官方拼写；不要无依据地全大写。 |
| PX-ENG-03 | 句子大小写适用于描述、句型提示、下拉/单复选项、树节点和表格内容：首词首字母大写，专有名词按官方拼写。 | `An error occurred while loading the DB2 library entry points.` | 组件规则另有指定时优先组件规则。 |
| PX-ENG-04 | 标题、菜单项、参数名及非完整句子的告警/通知消息开头省略冠词。 | `Add Node`，而非 `Add a Node`。 | 完整句、正文和需要自然语义的说明可使用冠词。 |
| PX-ENG-05 | 多个或数量可能大于 1 的对象使用复数；不得用 `(s)` 表示可能的单复数。变量数量的单位全称使用复数。 | `View Macros`；避免 `Service(s)`。 | 仅适用于单一对象时使用单数。 |

## 3. 组件结构与命名

| 规则 ID | 可判定要求 | 审查示例 | 例外/说明 |
|---|---|---|---|
| PX-CMP-01 | 页面、窗口、对话框、页签等标题使用词、词组或短语；属性设置界面采用名称结构，任务/配置界面采用“动词原形 + 宾语”；标题中不出现 `Dialog Box` 等界面元素类型词。 | `Add Node`；`Network Settings`。 | 查看详情时可使用对象名称；无单一代表字段时可拼接多个代表字段。 |
| PX-CMP-02 | 分组标题、区域标签使用名词或名词短语，末尾不加标点；控件可省略已由分组标题表达的重复词。 | 分组 `Alignment` 下使用 `Left`、`Right`。 | 框内控件仍需符合自身组件规则。 |
| PX-CMP-03 | 菜单名采用词或词组；菜单项优先使用动词原形或动词短语。 | `Select All`、`Paste`、`Delete`、`Export`。 | `New`、`About`、`Advanced` 等常用项可按既定写法。 |
| PX-CMP-04 | 命令按钮优先使用动词原形或动词短语；上下文中宾语唯一时可省略宾语；同一作用的按钮必须同名。高风险操作使用明确动作词，而非 `OK`/`Yes`。 | `Delete Node` 可在对象明确时简化为 `Delete`。 | 页面规范将“修改、设置/参数设置、扩容”等可能歧义的表单/模态框操作列为可使用 `确定 | 取消` 的场景。 |
| PX-CMP-05 | 选项可以是词、词组、短语或句子。句型选项不加句号；列表/复选框标签避免以 `Select` 开头；同组项目按明确顺序排列。 | 避免 `Select xxx from the Select xxx list` 式重复。 | 选项中包含命令或专有名词时保留其既定大小写。 |
| PX-CMP-06 | 参数名称、表头和文本框标签使用名词或名词短语，不包含 `Select` 等动词。 | `All Types`。 | 任务操作按钮可使用动词。 |
| PX-CMP-07 | 开关标签可用名词/名词短语或“动词原形 + 宾语”；不要添加 `whether`、`switch`、`toggle`，也避免有歧义的 `Open`/`Close`。同类开关取值用词应一致。 | `Enable Notifications`。 | 本地化中文开关应使用已批准的中文动词表达。 |
| PX-CMP-08 | 选项卡采用简洁名词短语，避免动宾结构；在不影响理解时省略 `Management`、`Settings` 等冗余词，避免滥用缩写。 | `Basic Information`。 | 向导步骤或任务流程可按流程语义单独定义。 |
| PX-CMP-09 | 占位符可用词、词组、短语或偶尔用句子；末尾不使用句号或省略号。 | `Enter a name`。 | 搜索与输入格式要求见反馈/搜索规则。 |
| PX-CMP-10 | 气泡卡片/Toast 标题与正文使用句子大小写；正文使用正常句子。 | 标题与正文分别按短标题、完整句处理。 | 中文语境下遵循对应的中文标点和句子规则。 |

## 4. 标点、时间和数据格式

| 规则 ID | 可判定要求 | 审查示例 | 例外/说明 |
|---|---|---|---|
| PX-PUN-01 | 中文界面使用中文标点，英文界面使用英文标点。英文逗号、冒号、句号后空一格；不推荐分号；连字符前后不留空格。 | `A maximum of 25 servers … (5 at most).` | URL、路径、代码、版本号和外部原值按其技术格式保留。 |
| PX-PUN-02 | 英文括号：左括号前留一格，右括号与后续单词间留一格，右括号与紧随标点之间不留空格。 | `tasks (5 at most).` | 无。 |
| PX-PUN-03 | 消息框、对话框、窗口主题句末不加句号；问句加问号。补充说明和完整描述信息正常使用标点；选项句末不加句号。 | 主题 `Delete file`；说明 `File integrity check failed.` | 句末为代码、路径或容易被误认为内容一部分的字符串时不加句号。名称、地点等非句子描述也不加句号。 |
| PX-PUN-04 | 省略号只用于隐藏超出容器的文字（并在悬停时显示全文）或表示操作进行中。 | `Searching…`。 | 不得用省略号替代完整的风险说明或输入提示。 |
| PX-DAT-01 | 无多时区场景使用 `YYYY-MM-DD HH:MM:SS`；多时区场景使用 `YYYY-MM-DDTHH:MM:SS ±HH:MM`；系统采用 24 小时制。 | `2019-01-25 19:08:16`。 | 秒或毫秒精度由业务确定。 |
| PX-DAT-02 | 列表在精确时间非业务必需时可使用相对时间；详情必须显示具体日期；可排序表格建议使用具体日期。 | 列表 `2 天前`；详情 `2018-07-01`。 | 业务要求精确时间时，列表也应显示具体时间。 |
| PX-DAT-03 | 时间单位、数字与空格按所在语言的时间格式规则统一；中英文不混用。 | 英文 `2 h 20 min 20 s`。 | 产品的中文组合时长格式须整体一致。 |

## 5. 搜索、反馈与确认

| 规则 ID | 可判定要求 | 审查示例 | 例外/说明 |
|---|---|---|---|
| PX-FBK-01 | 全表搜索且不需说明范围时，默认占位符为“搜索”；仅搜索特定字段时，明确显示可搜索字段。字段过长可用省略号截断，并在焦点状态展示完整范围。 | `请输入编号、用户名搜索`。 | 搜索字段命名以项目术语表为准。 |
| PX-FBK-02 | 操作失败/错误提示必须包含失败或错误原因，并给出适当建议；尽可能说明失败位置和修正方式。典型结构为“结果 + 方案”。 | `打开文件时出错，请检查文件是否为只读方式。` | 原因未知时写明可确认的结果与可执行建议，不得杜撰原因。 |
| PX-FBK-03 | 成功提示需表达实际完成的操作；英语结构按操作内容的语法类型选择。 | 中文：`保存数据成功`；英语：`Saving data succeeded.` | 英文成功提示的动词、名词和短语结构参照页面示例；项目术语优先。 |
| PX-FBK-04 | 操作确认提示展示具体操作对象的名称；批量操作还展示数量。 | `确定删除已选的 2 项任务吗？` | 高风险操作还应按产品安全规范表达不可逆性或影响范围。 |

## 6. 导出文件名与标题联动

| 规则 ID | 可判定要求 | 审查示例 | 例外/说明 |
|---|---|---|---|
| PX-NAM-01 | 数据文件导出名采用“功能模块名称（APP 名称）+ 特性名 + 用户名 + 时间戳”；模块名与 Portal 的功能模块名称一致；时间戳使用 `yyyymmddhhmmss`。 | `RANCM-CheckResult-admin-20170418082543.csv`。 | 模板类导出文件可直接使用模板本身名称。客户端/服务端时间取值按业务关联性或特殊业务指定。 |
| PX-NAM-02 | 页面初始标题与对应菜单名称一致；操作按钮引发的页面/弹窗标题与按钮名称对齐。 | 点击 `修改用户` 后标题为 `修改用户`。 | 查看对象详情时可用对象名称或多个代表字段拼接的标题。 |

## 审查输出规则

在报告中，以 `PX-` 编号注明设计系统依据；再给出原文、位置、问题和直接修改建议。不可将产品未定义的术语、技术参数或安全口径按本文件擅自改写。遇到源规范与通用规则库冲突时，使用本文件；遇到本文件未覆盖的中文基础规范时，再使用 `high-frequency-copy-rules.md`。

## 维护触发条件

以下情形必须将问题同时写入“规范待维护项”：来源网页内容更新；网页出现新组件类别；页面未显示版本号但规则发生变化；本文件与原网页矛盾；或审查中发现无法按已有规则判定的高频问题。
