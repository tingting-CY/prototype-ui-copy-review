# 审查前维度确认机制

将本文件用于用户提出“审查截图/页面/原型”，但**没有说明希望检查哪些维度**的场景。目的不是增加沟通步骤，而是让不熟悉规则模块的用户以自然语言选择范围，避免生成不适用的 `PX-`、`SPT-` 或治理类结论。

## 1. 是否需要追问

| 情况 | 执行动作 |
|---|---|
| 用户明确说“完整审查”“全面复查”“按当前 Skill 全部检查”或“默认全部”。 | 直接执行完整审查；`core`、`cross_page`、`coverage_gap` 使用 `on`，`px`、`spt`、`project` 仍按 `auto` 或已提供材料决定。 |
| 用户已指定任一具体维度、规则、页面差异或排除项。 | 不追问；按 `review-scope-configuration.md` 解析并执行。 |
| 用户一次提供一至五条明确 UI 文案，并直接询问是否合规、有没有问题或怎么改。 | 不追问；按 `SKILL.md` 的单条文案直接问答模式回答，`cross_page`、`coverage_gap`、`change_list` 设为 `off`。 |
| 用户仅提供材料并说“审查/看一下/检查文案”，没有说明维度。 | 先发起一次维度确认；不要先执行审查。 |
| 用户说“你推荐”“按常规检查”。 | 推荐组合 A，并询问是否按推荐组合开始；用户确认后执行。 |
| 用户处于紧急场景并明确要求“直接出结果，不用确认”。 | 直接按推荐组合 A 执行，并在报告中说明采用的默认范围。 |

只追问一次。用户可回复序号、组合名称、自然语言范围或“按推荐执行”；不要求用户理解 `HF-`、`PX-`、`SPT-` 等内部编号。

## 2. 面向用户的检查维度

| 选项 | 用户可见名称 | 检查内容 | 映射模块 |
|---|---|---|---|
| A | 基础文案与页面一致性（推荐） | 标题、字段、按钮、占位符、术语、标点、数字单位、状态表达；多个页面时同时检查一致性。 | `core: on`、`cross_page: auto` |
| B | 状态与提示信息 | 成功、失败、进行中、进度、空状态、错误原因、修复指引和风险提示。 | `core: on`、`spt: on` |
| C | 设计系统与品牌规范 | 项目设计系统、组件命名、品牌语气和用户提供的术语表。仅在用户提供或确认适用的设计系统时使用。 | `project: auto`、`px: on`（确认 PaletX/ZTE 时） |
| D | 跨页面/流程一致性 | 同一对象、动作、状态和关键流程在多页面、多截图或状态间的闭环。 | `cross_page: on` |
| E | 规范缺口与治理建议 | 不只找当前问题，还识别哪些真实场景尚无规范可依，供设计师补充规则。 | `coverage_gap: on` |
| F | 可交付修改清单 | 生成可直接交给设计/开发的 Markdown 修改清单。 | `change_list: on` |

A 是默认推荐基础组合。B、C、D、E、F 可与 A 组合，例如“选 A、B、F”。C 不能自动假定 PaletX/ZTE 适用；若用户只说“设计系统”，先要求其确认系统名称或提供规范链接。

## 3. 一次性确认问题

根据材料特点推荐最少的组合，但固定提供所有可选维度。使用以下格式，不自行扩展为多轮问题：

```markdown
我可以按以下维度审查。建议先选 **A + [推荐项]**；也可以直接回复“完整审查”或“按推荐执行”。

| 选项 | 检查维度 | 适用内容 |
|---|---|---|
| A | 基础文案与页面一致性 | 标题、字段、按钮、占位符、术语、格式与状态。 |
| B | 状态与提示信息 | 成功、失败、进度、空状态、风险与修复指引。 |
| C | 设计系统与品牌规范 | 仅在你确认适用的设计系统/术语表范围内检查。 |
| D | 跨页面/流程一致性 | 多页面、多个状态或完整流程时使用。 |
| E | 规范缺口与治理建议 | 识别后续需要补充的规范场景。 |
| F | Markdown 修改清单 | 输出可直接交付团队的修改清单。 |

请回复选项，例如 `A、B、F`；如本页不适用设计系统，也可以写“跳过 C”。
```

### 推荐项判定

| 材料信号 | 推荐组合 |
|---|---|
| 单页表单、列表、详情或静态截图 | A + F |
| 可见成功、失败、错误、进度、空状态或风险提示 | A + B + F |
| 两张及以上同流程页面/状态 | A + D + F |
| 用户提供设计系统链接、术语表或明确要求按某设计系统检查 | A + C + F |
| 用户要求完善设计规范、评审规则或建立治理待办 | A + E + F |

## 4. 执行映射与报告要求

1. 将用户的选项映射为模块配置；未选模块设为 `off`，而不是 `auto`。
2. 用户选 A 时，`core: on`；`cross_page` 仅在 D 或用户明确完整审查时启用。
3. 用户选 C 但未确认设计系统来源时，先询问一个来源问题，或将 C 标记为 `notice`；不得错误加载 `PX-`。
4. 用户选 F 时，只有存在明确原文、位置和直接改法时才生成清单；若没有可执行项，仍输出明确结论。
5. 在审查报告第一节以“审查维度确认”表格说明：用户选择、映射模块、页面级例外和实际状态。
6. 当用户选择“完整审查”，清单仍只加载实际适用的来源规则；`px: on` 只在 PaletX/ZTE 或用户提供的等效规则已确认适用时成立。
