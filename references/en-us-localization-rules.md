# en-US 本地化 UI 文案规则包

本文件只用于审查目标语言为美国英语（`en-US`）的用户可见 UI 文案。它与共用审查框架并行：共用框架负责证据、优先级、组件语境、P0–P3、跨页面一致性、UC 缺口和 COPY 清单；本文件负责英语语言质量与美国地区格式。它不是中译英翻译规范，也不覆盖其他英语变体。

## 使用协议

- 仅当用户明确指定 en-US、美国英语/美国地区英语，或项目配置明确将 locale 定为 `en-US` 时加载。若只写“英文”且地区会影响日期、拼写、货币或术语，先确认目标 locale；不将默认值偷偷设为 en-US。
- 输入优先提供配对字段：`source_zh`（中文源文案）、`target_en-US`（待审英文）、`component`、`screen/state`、`user/action`、`project_glossary`。中文仅作语义对照；目标文本仍按英语自然度、美国惯例和组件功能独立判断。
- 中文原文不是英文规则的依据。不得以逐字对应、中文语序、中文标点、中文短句习惯判错英文。若中英不一致但无法确认是否为有意本地化/业务差异，列为待确认，不擅自改业务语义。
- 证据与规则层级沿用主 Skill。项目术语表、品牌语气、无障碍或法务规范优先于本包。通用美式惯例不等于强制的项目规范；仅在清晰错误、理解风险或一致性证据充分时标为违反规则，其余标为建议统一。
- 引用规则时使用稳定 ID `EN-US-...`。同一问题合并受影响位置，直接改写保持原有功能、权限、数据范围、时限、价格、可逆性和状态真实。

## 规则细则

### 1. Locale、拼写与用词

- **EN-US-LOC-01a**：面向美国用户的普通词优先采用美式拼写，如 `color`、`center`、`organize`、`license`（名词/动词依句法），而非英式 `colour`、`centre`、`organise`、`licence`。若产品词、品牌名、代码、用户输入或项目术语表采用另一拼法，不改写；全产品同一词拼法不一致时标“建议统一”。
- **EN-US-LOC-01b**：选择美国常用词须服从产品语义和受众；例如 `ZIP code` 可用于美国邮编字段，但不把国际化邮政编码擅自改成 ZIP code。`cell phone`/`mobile phone`、`sign in`/`log in` 等存在产品惯例时保持一致，不单凭偏好判错。
- **EN-US-LOC-01c**：美式英语通常使用双引号作为主引号、句号/逗号置于闭引号内，但 UI 短标签、代码/精确字面值、法律引文和项目标点规范可例外。不得把中文标点习惯强套英文。

### 2. 语法、清晰度与简洁性

- **EN-US-GRAM-01a**：修正明确的语法错误，包括主谓不一致、可数名词单复数错误、冠词缺失导致不自然/歧义、代词指代不清、时态与真实状态冲突、错误介词及残缺句。先确认该片段是否刻意使用 UI 短语；按钮/标签不要求完整句。
- **EN-US-GRAM-01b**：使用自然、可理解的英语句序，不沿用中文直译式搭配。只在表达明显不自然、含义不清或与项目声调冲突时提出改写；语法正确的短句风格选择标“建议”，不冒充错误。
- **EN-US-PLN-01a**：优先使用常见词、具体动词和简短句子；删除不提供信息的套话/重复，但不得删掉限制、条件、责任、风险或必要解释。
- **EN-US-PLN-01b**：避免模糊代词（`it`, `this`, `that`）和抽象名词堆叠导致对象/动作不清。需要上下文才能确认对象时标待确认，不虚构对象。

### 3. 术语、大小写与一致性

- **EN-US-TERM-01a**：产品术语表和正式品牌写法优先。无项目规则时，采用 sentence case 作为普通界面默认建议（如 `Account settings`、`Create project`），但不把 Title Case 自动判为硬错；应按组件类型及同产品一致性判断。
- **EN-US-TERM-01b**：按钮/菜单动作使用一致的动词和对象；同一功能不要无理由切换 `Delete`/`Remove`、`Save`/`Apply`、`Sign in`/`Log in`。若业务后果不同（例如移出工作区 vs 永久删除），须保留区别并确认术语定义。
- **EN-US-TERM-01c**：句中普通词不应无规则大写；品牌、产品、正式功能名、缩写按项目词表。不要为了所谓“英文按钮必须首字母大写”改动品牌标准。

### 4. 组件语境与任务文案

- **EN-US-CMP-01a 标题/导航**：用可识别的对象或任务名称；同级标题语法形态平行。名词短语可用于页面标题（`Team members`），任务向导可用动作短语（`Invite teammates`）。标题不必强行写成句子。
- **EN-US-CMP-01b 按钮/链接**：以具体动作+必要对象为先（`Save changes`、`Invite member`、`View invoice`）；短按钮可省略主语和句末标点。避免只有 `OK`、`Submit`、`Click here` 等无法预测结果的文案，除非上下文唯一且属于低风险标准控件。按钮必须对应当前动作而非操作结果（执行中/结果状态不得冒充可执行入口）。
- **EN-US-CMP-01c 字段标签/占位符**：标签命名字段（`Email address`）；placeholder 提供示例或格式，不替代持久可见标签（除非确认组件/无障碍实现另有可靠标签）。不得仅为填满字段而重复标签；格式示例须与真实校验一致。
- **EN-US-CMP-01d 对话框**：标题说明决定/任务；正文说明对象及关键后果；动作按钮明确动作（`Delete project` / `Keep project`），高风险操作的主/次动作不能含糊。不要凭英文规范添加未证实的不可逆后果。
- **EN-US-CMP-01e 错误与帮助**：错误应说明发生了什么（已知时）、受影响对象/字段和用户可做的下一步；避免只写 `Error`、`Something went wrong`（除非作为有补充信息的概览）。输入错误要指出可接受格式/条件。避免命令式责备用户。
- **EN-US-CMP-01f 空状态**：区分“目前无内容”“搜索无匹配”“加载失败”“无权限”。有意义时给下一步动作；不把服务错误包装成“暂无数据”。

### 5. 状态与系统反馈

- **EN-US-STA-01a**：入口用动作原形（`Save`），进行中明确表达过程（`Saving…` / `Uploading…`），成功用结果状态（`Saved` / `Upload complete`），失败说明失败或已知原因及可行下一步。具体词形应按产品一致性确定。
- **EN-US-STA-01b**：不得将 `No results`、`No data`、`Access denied`、`Unavailable`、`Failed to load` 互换。它们对应不同真实状态。
- **EN-US-STA-01c**：重试、恢复、自动保存等承诺必须由材料/产品行为支持。`Try again` 只在确有可重试路径时建议；不要编造恢复时间或结果。
- **EN-US-STA-01d**：确认发生前用将来/条件表达，结果后用已完成状态；避免“已删除，是否确认？”一类时序冲突。

### 6. 标点、撇号与排版

- **EN-US-PUN-01a**：完整英文句子使用合理句末标点；按钮、菜单、标签、状态 chip 等短控件通常不加句号。完整帮助句和错误说明可用句号。按组件判断，不能把同一标点规则套到所有文本。
- **EN-US-PUN-01b**：英文疑问句用 `?`、感叹句用 `!`；不得夹用中文全角逗号/句号/冒号。逗号拼接两个完整独立句造成 run-on 时，应分句或使用合适连接词。
- **EN-US-PUN-01c**：撇号、弯引号和直引号须在同类内容中一致；代码、命令、键盘输入、可复制值使用精确字符，不得自动替换影响复制的字符。
- **EN-US-PUN-01d**：省略号按产品规范使用 `…` 或 `...` 并保持一致；进行中动画省略号不是语义替代品。避免连续多个感叹号、随意大写或装饰性标点。
- **EN-US-PUN-01e**：缩写、链接和变量周围空格及标点清晰；占位符变量、Markdown/HTML、代码、快捷键和用户生成内容不能因通用排版建议而改坏。

### 7. 美国地区格式

仅审查材料中实际出现或项目明确要求的格式；不得从单个例子推断整个产品必须采用某格式。

- **EN-US-NUM-01a 日期**：面向美国用户的日期默认可读写为 `Oct 19, 2026`；数字格式 `10/19/2026` 在美国常见但有歧义风险，国际受众/跨地区数据优先考虑月份文字或 ISO 8601。相对日期、完整日期和机器格式需区分。不得更改日期数值或时区含义。
- **EN-US-NUM-01b 时间**：美国界面常见 12 小时制 `9:05 AM`，但应尊重产品设置、用户地区、技术场景和既有一致性；AM/PM 大小写、空格、前导零按产品统一。若时间关系重要，核实/显示时区，不自行补造。
- **EN-US-NUM-01c 数字**：美式数字格式通常以逗号分组千位、句点作小数点（`1,234.5`）；本地化数值格式按 locale，不改原始标识符、代码或精确外部数据。
- **EN-US-NUM-01d 货币**：美国美元金额可写 `$12.50`；如果可能出现多货币或金额本身不清楚，应提供 `USD`/货币代码语境。不得擅自添加 `$`、币种、税费或小数精度。
- **EN-US-NUM-01e 单位与温度**：美国受众常见 US customary units，但全球产品可使用 SI、用户偏好或双单位；保持同屏和跨流程一致，写明必要单位。不得换算或改数值而未经授权。
- **EN-US-NUM-01f 电话/地址**：美国格式建议应匹配真实国家范围与输入校验；国际用户字段不应只接受美国邮编、州缩写或电话格式。ZIP/ZIP+4 仅在确认美国地址时适用。

### 8. 可访问与包容表达

- **EN-US-A11Y-01a**：链接文本应描述目的（优于孤立的 `Click here`）；可见标签需能独立辨认对象。审查文案，不对无法从材料确认的代码实现作结论。
- **EN-US-A11Y-01b**：不要只用颜色、位置、形状或“above/below”传递关键指令；补充可识别文字需基于真实界面和必要信息。
- **EN-US-A11Y-01c**：避免无必要的性别、年龄、能力、族裔或身份假设；优先直接称呼用户或使用中性表达。法律/行业术语或用户自选称谓保留。

### 9. 中英双语对照

- **EN-US-BI-01a 语义完整性**：对照源文检查对象、动作、否定、条件、数量、期限、权限、风险、结果和下一步是否保留。任何可能改变用户决策的缺失/增加，至少 P1；涉及不可逆/财务/安全/权限严重误导时按共用规则评为 P0。
- **EN-US-BI-01b 自然度优先**：允许为英语语法、信息顺序和 UI 习惯重组句子。非逐字对应不是错误；只报告语义差异、自然度问题或项目要求的一致性问题。
- **EN-US-BI-01c 文化/区域适配**：可本地化日期/时间/单位/例子，但不得默默更改政策、价格、资格、法律承诺、可用性或产品行为。地域例子需确认是示例还是限制条件。
- **EN-US-BI-01d 未知源意**：源文自身歧义、截断或业务含义不明时，将英语忠实度列为待确认，并明确需确认的最小问题；不要把模糊源文“修好”后当定稿。
- **EN-US-BI-01e 双语呈现**：双语对照用于审查证据和语义核对，不要求最终产品同时展示两种语言。报告须分别列 `中文源文` 与 `en-US 当前文案`，并标明是否为语义不一致；英文建议以英语给出，中文解释可使用中文。

### 10. 语气与承诺

- **EN-US-TONE-01a**：语气直接、尊重、以用户可采取的动作/事实为中心。避免责怪（`You did it wrong`）、羞辱、威胁或无必要的道歉堆叠；可用中性错误描述。
- **EN-US-TONE-01b**：避免未经证实的保证（`Your data is safe`、`This will never happen again`、`instant`）；保留经过批准的承诺和法定措辞。
- **EN-US-TONE-01c**：品牌温度/正式程度属于项目语气规则；无品牌材料时只标明显不一致，不以审查者个人喜好替换。

## 组件审查速查

| 组件 | 主要检查 | 常见合适形态 | 不应误判 |
|---|---|---|---|
| Page title | 对象/任务明确、同级平行 | `Billing history` | 名词短语不是语法错误 |
| Button | 具体动作、可预期结果 | `Save changes` | 不要求主语或句号 |
| Field label | 稳定命名字段 | `Email address` | Title Case 与 sentence case 需看项目规范 |
| Placeholder | 示例/格式且与验证一致 | `name@example.com` | 不能仅凭文案断定代码无标签 |
| Confirmation | 动作、对象、必要后果 | `Delete workspace` | 不添加未经证实的后果 |
| Error | 已知问题及可行下一步 | `Enter a valid email address.` | 不虚构错误根因 |
| Empty state | 区分无内容/无结果/错误 | `No invoices yet` | 不将失败伪装为空 |
| Progress/status | 过程和结果分明 | `Saving…` / `Saved` | 省略号不能弥补状态含糊 |
| Link | 目标明确、可单独理解 | `View billing details` | 需结合可见上下文判断重复 |

## 输出与严重度

沿用主 Skill 报告、COPY 清单和 UC 结构。每个可执行问题至少给：规则 ID、组件/位置、中文源文（如提供）、英文原文、问题/影响、自然的 en-US 改写、影响范围。双语差异需单独标识，不把语言流畅优化误写为忠实度错误。

- **P0**：可能引发重大错误操作、财务/安全/权限误解、不可逆损失或关键流程阻断。
- **P1**：源文与英文在对象、动作、否定、条件、关键状态/限制/期限上产生实质差异；或核心术语冲突。
- **P2**：明确语法、拼写、地区格式、组件文案或一致性问题，影响理解/完成任务。
- **P3**：无硬性规范冲突的可读性、简洁度或语气建议。明确标为建议，不强制改。

P0–P3 沿用共用框架定义；若某项规则没有足够语境，使用“待确认”，不为了打分而猜测。
