# 可选审查项配置协议

将本文件用于让用户按**任务**或**页面/截图**选择审查范围。配置仅控制本次审查加载哪些规则、生成哪些清单章节；不会修改 Skill 的规则库或来源状态。

## 1. 可配置模块

| 配置键 | 审查内容 | `auto` 默认行为 |
|---|---|---|
| `core` | 基础书写、术语、格式、组件文案、状态、跨页面一致性；对应适用的 `HF-` 规则。 | 启用。 |
| `px` | PaletX/ZTE 设计系统规则；对应 `PX-`。 | 仅当用户明确指定 PaletX/ZTE、提供对应设计系统，或页面明确属于该系统时启用。 |
| `spt` | 成功、失败、错误、异常和常用提示句型；对应 `SPT-`。 | 仅当材料包含提示信息、状态反馈或用户明确要求时启用。 |
| `project` | 用户提供的项目术语表、品牌、业务、安全、法务或其他专属规范。 | 有有效材料时启用。 |
| `cross_page` | 多页面、多截图或流程内的术语、动作和状态横向一致性。 | 材料覆盖两个及以上相关页面/状态时启用。 |
| `coverage_gap` | 未被当前已加载规范覆盖的真实文案场景；输出 `UC-` 清单。 | 启用。 |
| `change_list` | 可直接修改项的 Markdown 修改清单。 | 有明确原文、位置和改法的 P0/P1/P2 项时启用。 |

## 2. 取值与优先级

每个配置键可取以下值：

| 值 | 行为 |
|---|---|
| `auto` | 按上表的默认条件决定是否启用。 |
| `on` | 强制启用；若所需规范文件、来源或页面信息缺失，报告“未核实”或“待确认”，不得虚构规则。 |
| `off` | 跳过该模块的规则加载、问题判定和独立清单章节。 |
| `notice` | 不生成该模块的审查问题；仅在报告范围说明中提示该模块未审查。 |

优先级为：**页面级配置** > **任务级配置** > **用户自然语言明确指令** > **`auto` 默认行为**。当同一层级的指令冲突时，采用更窄的范围：`off` 优先于 `notice`，`notice` 优先于 `auto/on`。项目安全、法律或其他明确强制规范不能被本配置绕过；如用户要求跳过，记录为范围限制。

## 3. 输入方式

### 3.1 自然语言快捷指令

| 用户指令示例 | 等价配置 |
|---|---|
| `本页不涉及 PX 规范，跳过 PX。` | 任务或当前页面：`px: off` |
| `只查 HF 高频问题和提示信息。` | `core: on`、`spt: on`；其余模块：`off` |
| `不生成规范缺口清单。` | `coverage_gap: off` |
| `这张图只看状态和错误提示。` | `core: notice`、`spt: on`、其余模块：`off` |
| `页面 A 按 PX 审查，页面 B 不查 PX。` | 页面 A：`px: on`；页面 B：`px: off` |

### 3.2 结构化配置

在任务上下文中使用以下结构；未列出的模块视为 `auto`。

```text
<review_scope>
  <task_level>
    <core>auto</core>
    <px>auto</px>
    <spt>auto</spt>
    <project>auto</project>
    <cross_page>auto</cross_page>
    <coverage_gap>auto</coverage_gap>
    <change_list>auto</change_list>
  </task_level>
  <page id="upload-records">
    <px>off</px>
    <spt>on</spt>
  </page>
  <page id="version-management">
    <px>off</px>
    <spt>notice</spt>
  </page>
</review_scope>
```

## 4. 执行与输出

1. 在提取文案前，先解析任务级与页面级配置，形成页面—模块矩阵。
2. 对 `off` 模块，不读取其规则、不给出该模块问题、也不输出其专属章节。
3. 对 `notice` 模块，不产生问题；在报告“范围与限制”中写明“已按用户要求不审查 [模块]”。
4. 对 `on` 模块，按模块所需资源执行审查；来源或业务材料不足时，降级为“待确认/未核实”。
5. 对 `coverage_gap: off`，不要输出 `UC-` 清单，也不要将其换名并入待确认项。
6. 对 `change_list: off`，保留简洁审查报告，但不生成独立 Markdown 修改清单。
7. 在报告开头使用表格列出实际启用、跳过和仅提示的模块；页面级差异需在对应页面标题下再次标识。

## 5. 输出声明模板

```markdown
## 审查范围与模块配置

| 模块 | 实际状态 | 适用页面/截图 | 说明 |
|---|---|---|---|
| 核心规则（HF） | 已启用 | 全部 | 基础文案、组件、格式和状态。 |
| 设计系统（PX） | 已跳过 | 上传记录 | 用户说明该页面不涉及 PaletX/ZTE 规范。 |
| 提示信息（SPT） | 已启用 | 上传记录 | 审查失败原因与上传结果。 |
| 规范缺口（UC） | 已启用 | 全部 | 识别未覆盖场景。 |
```

当用户仅指定“跳过 PX”等简短指令时，不额外追问；按当前页面或本次任务范围执行，并在报告中明确说明。
