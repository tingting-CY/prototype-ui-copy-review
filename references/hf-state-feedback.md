# HF 动作、状态与反馈

仅在材料包含动作入口、进行中/完成状态、成功、失败、错误、空状态、校验或风险提示时读取本文件。一般反馈审查使用本文件；只有用户或项目明确指定 SPT 来源规范时，再读取 `system-prompt-patterns.md`。

## 动作与状态表达

| 规则 ID | 触发条件与判定 | 直接修改示例 | 例外 |
|---|---|---|---|
| HF-STA-01 | 动作入口使用已完成状态，或结果反馈使用动作原形，造成阶段混淆。 | 按钮 `已保存` → `保存`；Toast `保存` → `已保存` | 状态按钮、历史记录、禁用控件可使用结果/状态词。 |
| HF-STA-02 | 执行中状态未体现“正在进行”，或与成功状态共用文案。 | `保存`（加载中）→ `正在保存` | 图形进度已清晰表达且规范要求极短时，可用 `上传中`。 |
| HF-STA-03 | 成功反馈只写“操作成功”“处理完成”，未说明对象或动作。 | `操作成功` → `成员已添加` | 对象在同一视觉区域唯一且提示极短时可保留简短版本，但全局应一致。 |
| HF-STA-04 | 错误提示把失败原因、系统状态和用户下一步混为一谈，或仅写“系统异常”。 | `系统异常` → `保存失败，请稍后重试` | 不得编造未知原因；未知时只说明已知影响和可行下一步。 |
| HF-STA-05 | 将“无数据”“无搜索结果”“无权限”“功能不可用”“加载失败”误作同一状态。 | `暂无数据`（网络失败）→ `加载失败，请重试` | 无。 |
| HF-STA-06 | 危险操作确认使用泛化按钮，无法表达动作或后果。 | `确定`（删除弹窗）→ `删除成员` | 低风险、无歧义的信息确认可使用 `知道了` 或项目标准。 |
| HF-STA-07 | 确认正文在发生前使用已完成表述，或风险提示没有条件语气。 | `已删除全部记录，请确认` → `将删除全部记录，且不可恢复。是否继续？` | 无。 |
| HF-STA-08 | 同一流程混用“保存成功”“已保存”“保存完成”，但没有状态层级差异。 | 统一为产品既定成功口径。 | 若分别表示 Toast 与历史状态，须定义适用范围。 |
| HF-STA-09 | “已启用/已禁用”“开启/关闭”“可用/不可用”混用且未区分动作与状态。 | 动作用 `开启通知`；状态用 `通知已开启`；能力用 `通知不可用`。 | 组件库固定状态词优先。 |
| HF-STA-10 | 在用户无法自行解决的错误中承诺不可验证的结果或时间。 | `很快恢复` → `服务暂不可用，请稍后重试` | 已批准的 SLA、预计恢复时间或状态页链接。 |

## 校验、异常、空状态与风险

| 规则 ID | 触发条件与判定 | 直接修改示例 | 例外 |
|---|---|---|---|
| HF-FBK-01 | 校验错误未指向具体字段或规则。 | `输入错误` → `请输入 1–50 个字符` | 表单顶部汇总可简写，但必须能定位到字段。 |
| HF-FBK-02 | 把用户可修复问题表述为系统故障，或反之。 | `系统异常`（格式错误）→ `请输入有效的模型地址` | 无。 |
| HF-FBK-03 | 网络、服务、权限、数据不存在、并发冲突等不同错误共用同一文案。 | `操作失败` → 按已确认原因分别表达。 | 原因无法确认时使用中性失败文案，并提供重试/联系路径。 |
| HF-FBK-04 | 空状态没有交代当前为何为空，或把无结果误写为无数据。 | `暂无数据`（搜索）→ `未找到与“关键词”匹配的结果` | 字段空间不足时可在搜索框附近说明。 |
| HF-FBK-05 | 风险提示缺少触发条件、影响对象、后果或用户可采取的动作。 | `注意风险` → `删除“项目 A”后不可恢复。是否继续？` | 低风险信息提示可只说明事实。 |
| HF-FBK-06 | 敏感数据记录、导出、共享权限等操作提醒过弱，未说明范围。 | `开启日志` → `开启后将记录请求和响应数据，其中可能包含敏感信息。` | 具体敏感项、保留时间和权限遵循安全/法务口径。 |
