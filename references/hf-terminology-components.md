# HF 术语、命名与组件

仅在材料包含对象/动作命名、信息架构、标题、导航、按钮、字段、占位符或组件文案时读取本文件。先应用 `hf-core.md`。

## 术语、命名与信息架构

| 规则 ID | 触发条件与判定 | 直接修改示例 | 例外 |
|---|---|---|---|
| HF-TERM-01 | 同一业务对象在导航、标题、列表、详情、按钮和反馈中无理由使用不同名称。 | `成员管理`、`添加用户`、`人员已创建` → 统一对象名。 | 若“成员、用户、账号”代表不同层级，必须在术语表定义。 |
| HF-TERM-02 | 同一动作混用近义词，导致用户无法判断是否为同一功能。 | `新建项目`、`创建项目`、`添加项目` → 按业务语义选定主动作。 | 有真实业务差异时保留并说明。 |
| HF-TERM-03 | 字段名、技术参数或权限角色语义不明，改写可能改变业务定义。 | `小区容百分比`、`batch数` → 不猜测，列为待确认。 | 获得接口/产品定义后可补充首选名称。 |
| HF-TERM-04 | 页标题重复表达当前动作，或同级导航中对象名称不平行。 | `成员管理页面` → `成员管理` | 特殊落地页、引导页或营销页可用完整句标题。 |
| HF-TERM-05 | 同一角色在人称、权限提示和帮助文本中切换称谓。 | 确定角色体系与面向对象。 | 面向不同角色可不同，前提是对象清晰。 |
| HF-TERM-06 | 界面名称与帮助、错误、确认弹窗中的名称不同步。 | 按钮 `移除成员`，弹窗 `删除用户` → 统一对象和动作。 | “移除”和“删除”有真实数据保留差异时必须区分并解释。 |

## 组件文案与句法

| 规则 ID | 触发条件与判定 | 直接修改示例 | 例外 |
|---|---|---|---|
| HF-CMP-01 | 页面标题、导航或分组标题无法概括内容，或同级标题词性不平行。 | `管理成员`、`通知设置`、`日志` → 统一结构。 | 向导步骤、任务型页面可用动词短语。 |
| HF-CMP-02 | 按钮使用“确定”“提交”“操作”等泛化词，用户无法预期结果。 | `确定` → `保存更改`；`提交` → `提交申请` | 低风险通用确认、固定系统组件或上下文唯一限定的操作。 |
| HF-CMP-03 | 字段标签缺失，完全依赖占位符说明字段含义。 | 标签 `邮箱地址` + 占位符 `name@example.com` | 搜索框、全局命令框等上下文唯一的输入控件。 |
| HF-CMP-04 | 占位符承担长期说明、风险提示或多项规则，输入后信息消失。 | 占位符 `请输入名称` + 字段说明 `保存后不可修改。` | 无。 |
| HF-CMP-05 | 必填、选填、格式提示和错误提示相互矛盾。 | `手机号（选填）` + `手机号不能为空` → 按真实规则统一。 | 无。 |
| HF-CMP-06 | 同级按钮的动作粒度或语法形式不一致。 | `保存`、`取消操作`、`去查看` → 使用清晰动词短语。 | 主次层级不同可长短不同，但应体现真实层级。 |
| HF-CMP-07 | 禁用状态只保留不可点击按钮，未说明无法操作的原因。 | 就近显示 `请先填写模型地址`。 | 原因已在相邻字段明确显示时可省略。 |
| HF-CMP-08 | 成功、失败、空状态没有对应下一步，或下一步与状态不匹配。 | `暂无成员` → `暂未添加成员，去邀请成员` | 只读、无权限或确无后续动作时不强加 CTA。 |
| HF-CMP-09 | 删除、退出、覆盖、发布等高影响操作没有说明对象、后果或不可逆性。 | `确定删除？` → `删除“项目 A”后不可恢复。是否删除？` | 操作完全可撤销且撤销路径明确时可降低提示强度。 |
