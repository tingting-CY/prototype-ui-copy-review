# 高频界面文案错误规则库

将本规则库用于中文 UI 文案的**基础规范审查**。它提供默认基线，不替代产品设计系统、法务文本、无障碍规范或已批准的术语表。发生冲突时，遵循：**经确认的产品规范** > **经确认的业务/法务口径** > **本规则库**。

## 使用方式

先读取“通用判定与输出规则”，再按材料实际内容加载对应分类。每条规则均包含稳定编号，可在审查报告的“依据”列中引用。规则结果只能使用以下三类：

| 结果 | 使用条件 | 报告写法 |
|---|---|---|
| 违反规则 | 原文满足触发条件，且没有适用例外。 | `HF-PUN-01` |
| 建议统一 | 原型内部有不同写法，但未提供足以决定唯一标准的产品规范。 | `建议统一：HF-MIX-04` |
| 需确认 | 改写会影响业务含义、品牌术语、法务口径或技术定义。 | `需确认：HF-TERM-03` |

## 通用判定与输出规则

| 规则 ID | 判定规则 | 例外 | 审查动作 |
|---|---|---|---|
| HF-GEN-01 | 只报告可见、可读或由结构化材料明确提供的文字。 | 无。 | 模糊、截断、动态或未覆盖内容写为“未核实”，不得猜测。 |
| HF-GEN-02 | 一条问题只解决一个根因；同一根因影响多处时合并为系统性问题。 | 不同位置存在不同用户风险时可拆分。 | 列出所有受影响位置与唯一推荐写法。 |
| HF-GEN-03 | 修改建议不得改变权限、价格、时间、数据范围、可逆性、合规义务或系统真实状态。 | 经用户明确授权改写业务口径。 | 无法保持语义时标记“需确认”。 |
| HF-GEN-04 | 用组件语境判断正确性，不能将按钮、标题、字段标签和完整说明句按同一标点或句式规则处理。 | 无。 | 在报告中写明组件类型。 |
| HF-GEN-05 | 未提供产品规范时，不把偏好写成硬性错误。 | 明显错别字、语义矛盾、缺失谓语等基础错误除外。 | 将结论降为 P3 或“建议统一”。 |

# A. 标点、符号与空格

## A1. 句末标点与句子边界

| 规则 ID | 触发条件与判定 | 直接修改示例 | 例外 |
|---|---|---|---|
| HF-PUN-01 | 按钮、页签、菜单、导航、字段标签、状态标签使用完整句句号。此类短控件默认不加句末标点。 | `保存。` → `保存`；`待处理。` → `待处理` | 完整的多句说明、Toast、错误消息、空状态正文可使用句末标点。 |
| HF-PUN-02 | 完整陈述句、风险提示、错误说明或确认正文缺少必要句末标点，导致句子边界不清。 | `保存后配置立即生效请确认` → `保存后，配置将立即生效。请确认。` | 空间极窄且规范明确要求省略标点的单句提示。 |
| HF-PUN-03 | 中文自然语言句中无规则使用英文半角 `, . : ; ! ?`。 | `保存失败,请重试.` → `保存失败，请重试。` | URL、邮箱、代码、命令、正则、版本号和正式英文内容。 |
| HF-PUN-04 | 英文自然语言句中混入中文全角标点，且产品未规定双语排版例外。 | `Save failed，请 retry.` → `Save failed. Please retry.` 或完整中文化。 | 仅保留正式产品名、字段值或不可翻译的英文片段时，按其所在主语言处理。 |
| HF-PUN-05 | 中文完整句以三个半角句点 `...` 表示省略。 | `正在加载...` → `正在加载……` | 代码、文件扩展名、路径、版本号、英文原文或已定义的加载动画字符。 |
| HF-PUN-06 | 中文句中引号、括号形态与主语言不一致。 | `请选择 "高级模式"` → `请选择“高级模式”` | 引用代码、键名、命令、原始数据或正式英文短语时保留半角引号。 |
| HF-PUN-07 | 字段标签已通过布局与输入框关联，仍无规则追加冒号，造成同页标签形态混杂。 | `名称：` → `名称` | 表格行、键值对摘要、正文内引出说明时可使用冒号；同类组件必须统一。 |
| HF-PUN-08 | 同一对象的并列项随意混用顿号、逗号、斜杠、`&` 与“和”。 | `导入、导出/同步` → 根据真实关系改为 `导入、导出和同步` 或 `导入/导出` | 成对动作、技术路径、正式产品名可按已定义写法保留。 |
| HF-PUN-09 | 中文 UI 词组中斜杠两侧出现无意义空格，或同一页面同时使用 `A/B` 与 `A / B`。 | `导入 / 导出` → `导入/导出` | 数学式、路径表达、规范明确要求的分隔式排版。 |
| HF-PUN-10 | 范围、日期或版本无规则混用连字符 `-`、短横线 `–`、波浪线 `~` 与“至”。 | `1~10 条` → `1–10 条` 或 `1 至 10 条` | 先遵循产品规范；未提供时，同类数据在一个产品内选择一种写法。 |

## A2. 空格与不可见字符

| 规则 ID | 触发条件与判定 | 直接修改示例 | 例外 |
|---|---|---|---|
| HF-SPC-01 | 中文句中存在连续空格、行首行尾空格或标点前空格。 | `保存失败 ， 请重试` → `保存失败，请重试` | 代码块、等宽数据、刻意对齐的纯文本表格。 |
| HF-SPC-02 | 同一类中英文混排文案的空格策略不一致。 | `创建API 密钥`、`创建 API密钥` → 统一为 `创建 API 密钥` | 产品设计系统明确规定紧凑控件不加空格时，整类控件统一遵循该规范。 |
| HF-SPC-03 | 数字与中文量词、百分号、货币符号之间无规则插入空格。 | `共 10 条`、`60 %`、`¥ 99` → 按产品格式统一为 `共 10 条`、`60%`、`¥99` | 数值与独立拉丁单位（如 `10 MB`）可保留一个半角空格，但全产品必须一致。 |
| HF-SPC-04 | 把不可见换行、制表符或多个空格当作视觉对齐手段，导致复制、搜索或响应式排版异常。 | `用户名[多个空格]状态` → 使用布局组件，不在文案中填空格。 | 无。 |

# B. 时态、状态与动作表达

中文 UI 文案虽没有严格的语法时态变化，但必须用**动作、进行、结果、能力/限制**四类状态表达区分用户所处阶段。

| 规则 ID | 触发条件与判定 | 直接修改示例 | 例外 |
|---|---|---|---|
| HF-STA-01 | 动作入口（按钮、链接、菜单）使用已完成状态，或结果反馈使用动作原形，造成阶段混淆。 | 按钮 `已保存` → `保存`；Toast `保存` → `已保存` 或 `保存成功` | 状态按钮、历史记录、禁用控件可使用结果/状态词。 |
| HF-STA-02 | 执行中的状态未体现“正在进行”，或与成功状态共用同一文案。 | `保存`（加载中）→ `正在保存`；`上传成功`（进行中）→ `正在上传` | 图形进度已经清晰表达且规范要求极短标签时，可使用 `上传中`。 |
| HF-STA-03 | 成功反馈只写“操作成功”“处理完成”，未说明对象或动作。 | `操作成功` → `成员已添加`；`处理完成` → `报表已生成` | 操作对象在同一视觉区域内唯一且提示停留极短时，可保留简短版本，但全局应一致。 |
| HF-STA-04 | 错误提示把失败原因、系统状态和用户下一步混为一谈，或仅写“系统异常”。 | `系统异常` → `保存失败，请稍后重试`；已知原因时：`保存失败：名称不能为空` | 不得编造未知原因；未知时只说明已知影响和可行下一步。 |
| HF-STA-05 | 将“无数据”“无搜索结果”“无权限”“功能不可用”“加载失败”误用为同一状态。 | `暂无数据`（网络失败）→ `加载失败，请重试` | 无。不同状态必须分别表达。 |
| HF-STA-06 | 危险操作确认使用泛化按钮，无法表达将发生的动作或后果。 | `确定`（删除弹窗）→ `删除成员`；正文补充 `删除后不可恢复。` | 低风险、无歧义的常规信息确认可使用 `知道了` 或项目既定标准。 |
| HF-STA-07 | 确认正文在发生前使用已完成表述，或风险提示没有条件语气。 | `已删除全部记录，请确认` → `将删除全部记录，且不可恢复。是否继续？` | 无。 |
| HF-STA-08 | 同一流程混用“保存成功”“已保存”“保存完成”，但没有状态层级差异。 | 统一为 `已保存` 或产品既定的成功口径。 | 如果一项表示 Toast、一项表示历史状态，必须在规范中定义各自适用范围。 |
| HF-STA-09 | “已启用/已禁用”“开启/关闭”“可用/不可用”混用且未区分动作与状态。 | 开关动作使用 `开启通知`；状态使用 `通知已开启`；能力使用 `通知不可用`。 | 组件库已有固定状态词时优先遵循组件库。 |
| HF-STA-10 | 在用户无法自行解决的错误中承诺不可验证的结果或时间。 | `很快恢复` → `服务暂不可用，请稍后重试` | 已有经批准的 SLA、预计恢复时间或状态页链接时可使用。 |

# C. 中英文混排、大小写与技术词

| 规则 ID | 触发条件与判定 | 直接修改示例 | 例外 |
|---|---|---|---|
| HF-MIX-01 | 中文正文或说明中的独立英文词、缩写、数字未采用产品定义的间距规则，且同页出现不同写法。 | `支持OAuth登录`、`支持 OAuth登录` → 统一为 `支持 OAuth 登录` | 紧凑控件可采用无空格规则，但同类控件必须一致。 |
| HF-MIX-02 | 同一概念无规则切换中文全称、英文全称和缩写。 | `LLM`、`大模型`、`Large Language Model` → 选定主名称；首次说明可写 `LLM（大语言模型）` | 技术文档、代码字段和面向不同受众的内容可有层级差异，须在术语表声明。 |
| HF-MIX-03 | 正式品牌、产品名或技术协议的大小写被任意改写。 | `Github` → `GitHub`；`Oauth` → `OAuth`；`api key` → `API Key`（若术语表如此定义） | 用户输入值、外部系统返回值、代码和历史数据不应被强制改写。 |
| HF-MIX-04 | 中文+英文混合概念的连接方式不一致。 | `batch数`、`Batch 数`、`批处理数` → 选定一种主名称，如 `批处理数` | 确认技术含义前，不将该问题判为错词；报告为“建议统一/需确认”。 |
| HF-MIX-05 | 中文语境中出现未定义的英文操作词，增加理解成本。 | `点击 save` → `点击“保存”`；`click here` → `点击此处` | 面向开发者、命令行、代码字段或已有官方英文产品名。 |
| HF-MIX-06 | 以 `&`、`+`、`@` 代替中文连接词，且不是正式名称或技术语法。 | `导入&导出` → `导入和导出` 或 `导入/导出` | URL、邮箱、公式、标签、正式产品/功能名。 |
| HF-MIX-07 | 中文句中将英文复数、所有格或不必要冠词作为 UI 名称的一部分，造成不自然表述。 | `查看 Users` → `查看用户`；`编辑 the profile` → `编辑个人资料` | 菜单、外部系统名称或不可翻译的字段值。 |
| HF-MIX-08 | 同一技术术语在中文里无规则使用全角/半角括号、短横线、大小写或空格。 | `API密钥`、`API 密钥` → 按术语表统一为 `API 密钥` | 无；术语表优先。 |

# D. 数字、日期、时间、金额与单位

| 规则 ID | 触发条件与判定 | 直接修改示例 | 例外 |
|---|---|---|---|
| HF-NUM-01 | 同类数字无规则混用中文数字与阿拉伯数字。 | `共有三条`、`共 5 条` → 统一为 `共 3 条`、`共 5 条` | 品牌文案、固定成语、法律/金融文件或语义上必须使用中文数字的内容。 |
| HF-NUM-02 | 同类数据的小数位、千位分隔、正负号或单位精度不一致。 | `1,000`、`1000` → 统一一种；`1.5%`、`1.50%` → 按精度规则统一。 | 数据源原样展示且产品明确标注来源时可保留。 |
| HF-NUM-03 | 百分号、货币符号、温度等紧随单位的符号与数字间无规则加入空格。 | `60 %` → `60%`；`¥ 99` → `¥99` | 产品规范另有规定时优先。 |
| HF-NUM-04 | 独立拉丁单位的空格规则不一致。 | `10MB`、`10 MB` → 选定一种，如 `10 MB` | 技术协议、字段值、代码和设备厂商原始单位。 |
| HF-NUM-05 | 范围表达混用 `-`、`~`、`至`，或遗漏两端单位。 | `1-10GB` → `1–10 GB` 或 `1 至 10 GB` | 日期/版本号应遵循各自格式规则，不能套用一般范围规则。 |
| HF-NUM-06 | 同一信息层级无规则混用绝对日期、相对日期和不同日期格式。 | `2026/8/1`、`2026-08-01` → 统一为 `2026-08-01` | 消息时间线可使用 `刚刚/3 分钟前`；必须与列表、详情等绝对时间场景区分。 |
| HF-NUM-07 | 时间缺少时区、24/12 小时制或零填充规则，且同一产品出现多个格式。 | `9:5`、`09:05` → 统一为 `09:05` | 用户本地化设置、外部数据源或法律凭证要求不同格式时需明确来源。 |
| HF-NUM-08 | 输入提示、校验错误与实际可接受格式不一致。 | 占位符 `请输入 YYYY-MM-DD`，错误却写 `请输入 2026/01/01 格式` → 统一格式。 | 无。 |
| HF-NUM-09 | 将数值、单位和上限/下限写成歧义结构。 | `最大上传 10 文件` → `最多上传 10 个文件`；`限制 10M` → `文件大小不得超过 10 MB` | 无。 |

# E. 术语、命名与信息架构

| 规则 ID | 触发条件与判定 | 直接修改示例 | 例外 |
|---|---|---|---|
| HF-TERM-01 | 同一业务对象在导航、标题、列表、详情、按钮和反馈中无理由使用不同名称。 | `成员管理`、`添加用户`、`人员已创建` → 统一为 `成员管理`、`添加成员`、`成员已添加` | 若“成员、用户、账号”代表不同层级，必须在术语表定义范围。 |
| HF-TERM-02 | 同一动作混用近义词，导致用户无法判断是否为同一功能。 | `新建项目`、`创建项目`、`添加项目` → 按业务语义选定主动作。 | 真实业务差异，例如“新建空项目”和“添加现有项目”，应保留并说明。 |
| HF-TERM-03 | 字段名、技术参数或权限角色语义不明，改写可能改变业务定义。 | `小区容百分比`、`batch数` → 不直接猜测，列为需确认。 | 获得接口/产品定义后，可补充首选名称。 |
| HF-TERM-04 | 页标题重复表达当前动作，或对象名称在同级导航中不平行。 | 页标题 `成员管理页面` → `成员管理`；`系统设置/管理成员/日志` → 统一名词或动宾结构。 | 特殊落地页、引导页或营销页可采用完整句标题。 |
| HF-TERM-05 | 同一角色在人称、权限提示和帮助文本中切换称谓。 | `管理员可编辑`、`您没有管理权限`、`组织拥有者` → 确定角色体系与面向对象。 | 面向不同角色的内容可不同，前提是对象清晰。 |
| HF-TERM-06 | 界面名称与帮助、错误、确认弹窗中的名称不同步。 | 按钮 `移除成员`，弹窗 `删除用户` → 统一为同一对象和动作。 | “移除”和“删除”在数据保留上有真实差异时必须区分，并解释后果。 |

# F. 组件文案与句法

| 规则 ID | 触发条件与判定 | 直接修改示例 | 例外 |
|---|---|---|---|
| HF-CMP-01 | 页面标题、导航或分组标题使用不完整动作句，无法概括当前内容；或同级标题词性不平行。 | `管理成员`、`通知设置`、`日志` → 统一为名词型或动宾型。 | 向导步骤、任务型页面可使用动词短语。 |
| HF-CMP-02 | 按钮使用“确定”“提交”“操作”等泛化词，用户无法预期结果。 | `确定` → `保存更改`；`提交` → `提交申请` | 低风险通用确认、系统组件固定文案或上下文已唯一限定的操作。 |
| HF-CMP-03 | 字段标签缺失，完全依赖占位符说明字段含义。 | 仅有 `请输入邮箱` → 标签 `邮箱地址` + 占位符 `name@example.com` | 搜索框、全局命令框等上下文唯一的输入控件。 |
| HF-CMP-04 | 占位符承担长期说明、风险提示或多项规则，输入后信息消失。 | `请输入，保存后不可修改` → 占位符 `请输入名称` + 字段说明 `保存后不可修改。` | 无。 |
| HF-CMP-05 | 必填、选填、格式提示和错误提示相互矛盾。 | 标签 `手机号（选填）` + 错误 `手机号不能为空` → 按真实规则统一。 | 无。 |
| HF-CMP-06 | 同级按钮的动作粒度或语法形式不一致。 | `保存`、`取消操作`、`去查看` → 统一为 `保存`、`取消`、`查看详情` 等清晰动词短语。 | 主次层级不同可长短不同，但应体现真实层级。 |
| HF-CMP-07 | 禁用状态只保留不可点击按钮，未说明无法操作的原因。 | `保存`（禁用）→ `请先填写模型地址` 或就近字段错误提示。 | 原因已在相邻字段明确显示且重复会造成噪声时可省略。 |
| HF-CMP-08 | 成功、失败、空状态没有对应下一步，或提供与实际状态不匹配的下一步。 | `暂无成员` → `暂未添加成员，去邀请成员` | 只读页面、无权限用户或确实不存在后续动作时，不必强加 CTA。 |
| HF-CMP-09 | 删除、退出、覆盖、发布等高影响操作没有说明对象、后果或不可逆性。 | `确定删除？` → `删除“项目 A”后不可恢复。是否删除？` | 操作完全可撤销且撤销路径明确时，可按规范降低提示强度。 |

# G. 语法、语气与可读性

| 规则 ID | 触发条件与判定 | 直接修改示例 | 例外 |
|---|---|---|---|
| HF-LNG-01 | 句子缺少谓语、宾语或必要的逻辑连接，导致无法判断发生什么。 | `开启后后台日志中将完整的请求数据` → `开启后，后台日志将完整记录请求数据。` | 词组型标题、标签、按钮和状态标签不要求完整句。 |
| HF-LNG-02 | 否定词、范围词和条件词位置产生歧义。 | `不支持所有成员删除` → `不支持删除所有成员` 或 `仅管理员可删除成员` | 无；必须按真实权限重写。 |
| HF-LNG-03 | 并列项不平行，或修饰关系不清。 | `创建、编辑和删除项目权限` → `创建项目、编辑项目和删除项目的权限` | 空间非常受限时可通过表头、图标或层级清晰表达省略。 |
| HF-LNG-04 | 无规则混用“您/你”、第一人称、无主语命令式和过度拟人化语气。 | `你暂无权限`、`我们无法保存` → 按品牌规范统一为 `您暂无权限`、`保存失败` | 客服/社交产品可使用特定人格化语气，但须全局统一。 |
| HF-LNG-05 | 使用责备、模糊或无法行动的表达。 | `您输入错误` → `请输入有效的邮箱地址`；`请正确操作` → 明确下一步。 | 安全告警可使用强提醒，但不得攻击用户。 |
| HF-LNG-06 | 无意义的冗余词降低扫描效率。 | `请您点击按钮进行保存操作` → `保存` 或 `点击“保存”` | 教学引导中可保留必要的步骤描述。 |
| HF-LNG-07 | 简繁体、异体字或地区用词在同一 zh-CN 产品中无规则混用。 | `设置`、`設定` → 统一为 `设置` | 面向多地区时按 locale 切换，不在同一界面混用。 |
| HF-LNG-08 | 使用内部缩写、实现术语或未解释的错误码作为面向普通用户的唯一说明。 | `RPC 调用失败` → `连接服务失败，请稍后重试`；必要时附可复制错误码。 | 开发者工具、管理员诊断页或已定义的技术术语。 |

# H. 校验、异常、空状态与风险提示

| 规则 ID | 触发条件与判定 | 直接修改示例 | 例外 |
|---|---|---|---|
| HF-FBK-01 | 校验错误未指向具体字段或具体规则。 | `输入错误` → `请输入 1–50 个字符` | 表单顶部汇总可简写，但必须能定位到字段。 |
| HF-FBK-02 | 错误提示把用户可修复的问题表述为系统故障，或反之。 | `系统异常`（格式错误）→ `请输入有效的模型地址` | 无。 |
| HF-FBK-03 | 网络、服务、权限、数据不存在、并发冲突等不同错误共用同一文案。 | `操作失败` → 按可确认原因分别写 `无权限保存此配置`、`网络连接失败，请重试`。 | 原因无法确认时使用中性失败文案，并提供重试/联系路径。 |
| HF-FBK-04 | 空状态没有交代“当前为什么为空”，或把无结果误写为无数据。 | `暂无数据`（搜索）→ `未找到与“关键词”匹配的结果` | 字段空间不足时，可在搜索框附近说明。 |
| HF-FBK-05 | 风险提示缺少触发条件、影响对象、后果或用户可采取的动作。 | `注意风险` → `删除“项目 A”后不可恢复。是否继续？` | 低风险信息提示可只说明事实。 |
| HF-FBK-06 | 记录敏感数据、导出数据、共享权限等操作使用过于弱的提醒，未说明范围。 | `开启日志` → `开启后将记录请求和响应数据，其中可能包含敏感信息。` | 具体敏感项、保留时间和访问权限需遵循安全/法务批准口径。 |

# I. 规则维护要求

将频繁出现、需要团队统一的规则转写为产品设计系统条目，而不要长期依赖审查员临时判断。每条产品规则至少维护以下字段。

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 稳定且唯一，例如 `COPY-PUN-001`。 |
| `category` | 是 | 标点、术语、状态、格式、组件、合规等。 |
| `rule` | 是 | 可判定的要求，避免“尽量”“适当”等模糊词。 |
| `scope` | 是 | 适用语言、端、组件、页面类型或用户角色。 |
| `good_examples` | 是 | 至少一个正确示例。 |
| `avoid_examples` | 建议 | 常见错误示例；必要时写出错误原因。 |
| `exceptions` | 是 | 不适用的合法场景；无例外时明确写“无”。 |
| `severity_default` | 建议 | 默认 P1/P2/P3，仅作初始分级。 |
| `owner` 与 `version` | 是 | 便于变更、回溯与审查报告引用。 |

审查发现同类问题反复出现、现有规则相互矛盾、无法判定唯一写法或示例与规则冲突时，不要只提出单页改字；同时在“规范待维护项”中提出新增、修订、合并或废弃规则的建议。
